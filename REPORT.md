# Аналитический отчет по использованию SDK в Android-приложениях RuStore

## 1. Сводная статистика
В ходе исследования 10 мобильных приложений из каталога RuStore были идентифицированы следующие ключевые SDK (всего 13 SDK из базы в 25 записей, 35 пар «приложение — SDK»):
- **Аналитика:** AppMetrica обнаружена в 9 из 10 приложений, MyTracker — в 3 из 10, Firebase Analytics — в 3 из 10.
- **Push-уведомления:** RuStore Push SDK установлен в 5 из 10 приложений, Firebase Cloud Messaging (FCM) — в 3, Huawei HMS Push — в 1.
- **Платежные системы:** T-Bank Acquiring зафиксирован в банковском приложении Т-Банк; RuStore Billing и SberPay в выборке не обнаружены.
- **Картография:** Yandex MapKit обнаружен в 2 приложениях (Яндекс Карты, Авито), 2GIS Map SDK — в 2ГИС.
- **Прочее:** Sentry (crash reporting) — в 2 приложениях, Yandex Mobile Ads — в 2, Google Sign-In — в 2, VK ID — в 1.

## 2. Анализ импортозамещения
На отечественные решения приходится 24 из 35 найденных пар «приложение — SDK» (68,6 %), на зарубежные — 11 (31,4 %). Наблюдается выраженный тренд на отечественную экосистему, но полной замены нет:
1. **Push-сервисы:** RuStore Push SDK (5 из 10) используется в финансовом, торговом и навигационном сегментах, тогда как RUTUBE, Яндекс Музыка и Telegram остаются на FCM. Одновременно RuStore Push и FCM ни в одном приложении выборки не найдены.
2. **Аналитика:** Абсолютным лидером является Yandex AppMetrica (9 из 10), следом идет VK MyTracker (3 из 10). Google Analytics for Firebase сохраняется в 3 приложениях, но везде работает совместно с AppMetrica.
3. **Авторизация:** VK ID найден только в Авито, Google Sign-In — в RUTUBE и Яндекс Музыке; Sber ID и T-Bank ID в выборке не обнаружены.
4. **Остаточная зависимость:** зарубежные компоненты сохраняются в push-инфраструктуре (FCM, Huawei HMS), мониторинге сбоев (Sentry) и авторизации (Google Sign-In).

Выводы относятся только к исследованной выборке из 10 приложений.

## 3. Сложности статического анализа
При проведении анализа были выявлены следующие трудности:
- **Обфускация (ProGuard / R8):** Некоторые внутренние классы SDK переименованы в короткие идентификаторы (например, `a.b.c`), однако корневые package namespaces, объявления сервисов в `AndroidManifest.xml` и имена `.so`-файлов сохраняются, поэтому детекция велась по пакетам, манифесту и нативным библиотекам.
- **Динамическая загрузка:** Нативные библиотеки (`.so`) используются преимущественно тяжелыми движками (карты, Sentry, графические библиотеки); код, подгружаемый после установки, и отсутствующие split-APK не учитываются.
- **Ограничения вывода:** Наличие компонентов SDK не доказывает использование его функций, а отсутствие платежного SDK не означает отсутствия оплаты в приложении.
